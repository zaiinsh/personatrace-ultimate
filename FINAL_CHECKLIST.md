## 1. Key-first architecture — DONE
- [x] Local key vault: features/v6.py save_key/load_keys/delete_key, file
      .personatrace_keys.json, chmod 0600, added to .gitignore, never logged,

      HikerAPI, YouTube, Brave, Tavily, Serper, GitHub, Shodan, generic
      aggregator. 200 = verified, 401/403 = key invalid, 429 = blocked.

## 7. Honest limits remaining (NOT fixed by v6, do not claim otherwise)
- Instagram full data without a key/login: gated. Public web returned
  blocked (429) for both Instagram-only usernames in live runs. This is
  IP-dependent and may vary, but it is not a reliable free route.
- X timeline/search and TikTok followers/likers: gated_paid without a key.
- Search dorking without a search key: DDG HTML fallback returned 0
  snippets in live runs. Add a Brave/Tavily/Serper key for reliable dorks.
- Full comment history, full follower lists, stories, private profiles:
  not available without an aggregator key or consented login, and
  private profiles are never attempted.
- Wayback/crt.sh/DNS for username seeds: degraded (those adapters need
  a domain seed); they are not a failure of the username search.
- GUI live search is slow (tens of seconds) because it runs all adapters
  + analysis + dossier; that is a real usability limit, not a bug to hide.
- No key was supplied during verification, so all key routes (HikerAPI,
  YouTube, search APIs, Shodan full) are verified only by injected-fetcher
  tests and by code inspection, NOT by a live run with a real key.
  The investigator must verify their own key with --verify after adding it.
